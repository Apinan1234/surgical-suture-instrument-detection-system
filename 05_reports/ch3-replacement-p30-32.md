## 3.4 การพัฒนาระบบและส่วนประกอบของโปรแกรม

ระบบพัฒนาด้วยภาษา Python ทำงานบนเว็บเซิร์ฟเวอร์ FastAPI เพียงกระบวนการเดียว และแบ่ง
ส่วนประกอบของโปรแกรมออกเป็น 4 โมดูลตามลำดับการไหลของข้อมูล สถานะการทำงานทั้งหมดถูก
บันทึกลงไฟล์ JSON ไฟล์เดียว โดยไม่ใช้ระบบจัดการฐานข้อมูล เนื่องจากระบบนี้เป็นเครื่องมือสนับสนุน
การจัดเตรียมชุดข้อมูลที่มีผู้ใช้งานคนเดียว การเก็บสถานะเป็นไฟล์เดียวทำให้ย้ายระบบไปยังเครื่องอื่นได้
ด้วยการคัดลอกโฟลเดอร์ และสำรองข้อมูลได้ด้วยการคัดลอกไฟล์เพียงไฟล์เดียว

### 3.4.1 โมดูลสกัดเฟรมภาพจากวิดีโอ (Frame Extraction Module)

พัฒนาด้วยไลบรารี OpenCV ทำหน้าที่รับไฟล์วิดีโอที่ผู้ใช้อัปโหลดผ่านหน้าเว็บ ตรวจสอบรูปแบบไฟล์
แล้วอ่านวิดีโอทีละเฟรมเพื่อคัดเลือกเฟรมตามระยะห่างที่ผู้ใช้กำหนด (frame interval) เฟรมที่คัดเลือกได้
จะถูกบันทึกเป็นไฟล์ภาพนิ่งลงในโฟลเดอร์ของงานนั้น พร้อมบันทึกรายการเฟรมลงในสถานะของระบบ
โมดูลนี้ทำงานเป็นงานเบื้องหลังที่รายงานความคืบหน้าเป็นระยะ และผู้ใช้สามารถสั่งหยุดกลางคันได้

### 3.4.2 โมดูลตรวจจับวัตถุ (Object Detection Module)

พัฒนาด้วยเฟรมเวิร์ก PyTorch ร่วมกับไลบรารี Ultralytics โดยใช้แบบจำลอง YOLO11n ที่ผ่านการ
ฝึกฝนด้วยชุดข้อมูลของโครงงานนี้ ผู้ใช้ต้องเลือกและโหลดแบบจำลองเข้าหน่วยความจำก่อน จากนั้นจึง
สั่งประมวลผลเฟรมภาพเป็นชุด ผลลัพธ์ของแต่ละเฟรมประกอบด้วยรหัสคลาส พิกัดกรอบล้อมรอบวัตถุ
ในรูปแบบสัดส่วนต่อขนาดภาพ (normalized) และค่าความเชื่อมั่น ซึ่งถูกบันทึกรวมไว้กับข้อมูลของเฟรมนั้น

ในส่วนของการเลือกแบบจำลอง ระบบจะอ่านจำนวนคลาสจากไฟล์น้ำหนักแต่ละไฟล์มาแสดงกำกับไว้
และจัดกลุ่มแยกระหว่างแบบจำลองของโครงงาน แบบจำลองตั้งต้นทั่วไป และจุดบันทึกระหว่างการฝึกฝน
การแสดงจำนวนคลาสนี้เพิ่มเข้ามาเพื่อป้องกันความผิดพลาดจากการโหลดแบบจำลองผิดตัว ซึ่งเป็น
ความผิดพลาดที่ตรวจพบได้ยาก เพราะระบบยังทำงานได้ตามปกติแต่ให้ผลเป็นคลาสของชุดข้อมูลอื่น

### 3.4.3 โมดูลกำกับและตรวจทานข้อมูล (Annotation and Review Module)

ส่วนติดต่อผู้ใช้ทำงานบนพื้นที่วาดภาพ (canvas) ในเบราว์เซอร์ รองรับการกำกับข้อมูลด้วยกรอบ
ล้อมรอบวัตถุ รูปหลายเหลี่ยม จุดสำคัญ และกรอบแบบมีมุมหมุน ผู้ใช้สามารถเรียกแบบจำลองมาช่วย
เสนอกรอบในเฟรมที่กำลังทำอยู่ แล้วยืนยันหรือปฏิเสธเป็นรายกรอบ นอกจากนี้ยังมีฟังก์ชันที่ออกแบบ
มาสำหรับข้อมูลที่มาจากวิดีโอโดยเฉพาะ ได้แก่ การประมาณค่ากรอบระหว่างเฟรมหลัก (interpolation)
การยืนยันผลทั้งช่วงเฟรมในคราวเดียว การแก้ไขคลาสหรือลบกรอบเป็นกลุ่ม และการอ่านข้อความในภาพ
ด้วย Tesseract OCR การแก้ไขทุกครั้งจะเพิ่มเลขรุ่นของเฟรมนั้น เพื่อให้ตรวจสอบย้อนหลังได้ว่าข้อมูล
ถูกแก้ไขไปแล้วกี่ครั้ง

### 3.4.4 โมดูลส่งออกชุดข้อมูล (Dataset Export Module)

ทำหน้าที่รวบรวมเฟรมที่ผ่านการตรวจทานแล้วมาจัดเป็นชุดข้อมูลในรูปแบบ YOLO พร้อมไฟล์กำหนดค่า
ชุดข้อมูล โดยผู้ใช้กำหนดสัดส่วนการแบ่งชุดฝึกฝน ชุดตรวจสอบ และชุดทดสอบได้ และเลือกเปิดการ
เพิ่มขยายข้อมูลในขั้นตอนส่งออกได้ ผลลัพธ์ถูกบีบอัดเป็นไฟล์เดียวสำหรับดาวน์โหลด

### 3.4.5 การควบคุมการเข้าถึงระบบ (Access Control)

ระบบใช้การยืนยันตัวตนด้วยรหัสผ่านร่วมชุดเดียว (shared secret) โดยผู้ใช้กรอกรหัสผ่านหนึ่งครั้ง
แล้วระบบจะออกโทเค็นเก็บไว้ในคุกกี้ที่สคริปต์ฝั่งเบราว์เซอร์อ่านไม่ได้ ทุกเส้นทางเรียกใช้งานของระบบ
ยกเว้นการตรวจสอบสถานะและการเข้า–ออกระบบ จะถูกปฏิเสธหากไม่มีโทเค็นที่ยังไม่หมดอายุ

**ระบบไม่จัดเก็บข้อมูลส่วนบุคคลของผู้ใช้** ไม่มีชื่อผู้ใช้ ไม่มีอีเมล ไม่มีตารางบัญชีผู้ใช้ และไม่มีหน้า
สมัครสมาชิก การตัดสินใจนี้เป็นไปตามลักษณะการใช้งานจริงของระบบ ซึ่งเป็นเครื่องมือภายในสำหรับ
จัดเตรียมชุดข้อมูลที่มีผู้ใช้งานคนเดียว จึงไม่มีความจำเป็นต้องแยกสิทธิ์ระหว่างผู้ใช้ หรือระบุว่าผู้ใด
เป็นผู้กำกับข้อมูลกรอบใด การเพิ่มระบบบัญชีผู้ใช้ในบริบทนี้จะเพิ่มความซับซ้อนโดยไม่ได้ประโยชน์เพิ่มขึ้น

อนึ่ง การเข้าสู่ระบบไม่เกี่ยวข้องกับการบันทึกความคืบหน้าของงาน เนื่องจากผลการกำกับข้อมูลทั้งหมด
ถูกบันทึกไว้ที่ฝั่งเซิร์ฟเวอร์ตลอดเวลา ผู้ใช้จึงสามารถปิดเบราว์เซอร์แล้วกลับมาทำงานต่อในภายหลังได้
โดยข้อมูลไม่สูญหาย การเข้าสู่ระบบทำหน้าที่ควบคุมสิทธิ์การเข้าถึงเท่านั้น

## 3.8 ตัวชี้วัด แบบแผนการทดลอง และโปรโตคอลการวัดผล

### 3.8.1 แบบแผนการทดลองแบบ A/B

การทดลองออกแบบให้มีตัวแปรต้นเพียงตัวเดียว คือการเพิ่มขยายข้อมูล (data augmentation) โดย
ควบคุมตัวแปรอื่นทั้งหมดให้เหมือนกันทุกประการระหว่างสองรอบการทดลอง ได้แก่ ชุดข้อมูล แบบจำลอง
ตั้งต้น จำนวนรอบการฝึก ขนาดกลุ่มตัวอย่าง ขนาดภาพนำเข้า และค่าสุ่มตั้งต้น ค่าพารามิเตอร์ที่ใช้จริง
ถูกตรวจสอบย้อนกลับจากไฟล์บันทึกค่าที่ระบบแปลงค่าแล้วของแต่ละรอบ เพื่อยืนยันว่าความแตกต่าง
เกิดขึ้นเฉพาะกลุ่มพารามิเตอร์ที่ตั้งใจให้ต่างเท่านั้น

| พารามิเตอร์ | รอบ A (ไม่เพิ่มขยายข้อมูล) | รอบ B (เพิ่มขยายข้อมูล) |
|---|---|---|
| แบบจำลองตั้งต้น | yolo11n.pt | yolo11n.pt |
| จำนวนรอบการฝึก (epochs) | 50 | 50 |
| ขนาดกลุ่มตัวอย่าง (batch) | 8 | 8 |
| ขนาดภาพนำเข้า (imgsz) | 640 | 640 |
| ค่าสุ่มตั้งต้น (seed) | 42 | 42 |
| การทำซ้ำได้ (deterministic) | true | true |
| อัตราการเรียนรู้ตั้งต้น (lr0) | 0.01 | 0.01 |
| อัตราการเรียนรู้สุดท้าย (lrf) | 0.01 | 0.01 |
| momentum | 0.937 | 0.937 |
| weight decay | 0.0005 | 0.0005 |
| รอบอุ่นเครื่อง (warmup epochs) | 3 | 3 |
| **mosaic** | **0.0** | **1.0** |
| **fliplr** | **0.0** | **0.5** |
| **scale** | **0.0** | **0.5** |
| **translate** | **0.0** | **0.1** |
| **hsv_h / hsv_s / hsv_v** | **0.0 / 0.0 / 0.0** | **0.015 / 0.7 / 0.4** |
| degrees, shear, perspective, flipud, mixup, cutmix, copy_paste | 0.0 | 0.0 |

การปิดการเพิ่มขยายข้อมูลในรอบ A ทำแบบครบทุกพารามิเตอร์ ไม่ใช่เพียงปิด mosaic เท่านั้น ส่วน
พารามิเตอร์ erasing มีค่าเท่ากันทั้งสองรอบ (0.4) จึงไม่นับเป็นตัวแปรที่แตกต่าง

### 3.8.2 ตัวชี้วัดที่ใช้

ประเมินด้วยตัวชี้วัดมาตรฐานของงานตรวจจับวัตถุ โดยถือว่าการทำนายถูกต้องเมื่อค่าการซ้อนทับระหว่าง
กรอบที่ทำนายกับกรอบจริง (Intersection over Union: IoU) ไม่น้อยกว่าเกณฑ์ที่กำหนด

- **Precision** = TP / (TP + FP) — สัดส่วนของสิ่งที่แบบจำลองทำนายว่าใช่ แล้วใช่จริง
- **Recall** = TP / (TP + FN) — สัดส่วนของวัตถุจริงทั้งหมดที่แบบจำลองตรวจพบได้
- **F1-score** = 2 × (Precision × Recall) / (Precision + Recall)
- **AP** = พื้นที่ใต้กราฟ Precision–Recall ของคลาสหนึ่ง
- **mAP@50** = ค่าเฉลี่ยของ AP ทุกคลาส ที่เกณฑ์ IoU เท่ากับ 0.50
- **mAP@50-95** = ค่าเฉลี่ยของ mAP ที่เกณฑ์ IoU ตั้งแต่ 0.50 ถึง 0.95 เพิ่มทีละ 0.05 ซึ่งเข้มงวดกว่า
  เพราะให้คะแนนความแม่นยำของตำแหน่งกรอบด้วย ไม่ใช่เพียงว่าตรวจพบหรือไม่

### 3.8.3 โปรโตคอลการวัดผล

- ชุดข้อมูลถูกแบ่งเป็นชุดฝึกฝน ชุดตรวจสอบ และชุดทดสอบ แบบไม่ทับซ้อนกัน
- **ชุดตรวจสอบ (validation) ใช้สำหรับเลือกจุดบันทึกแบบจำลองที่ดีที่สุดระหว่างการฝึกฝนเท่านั้น**
- **ชุดทดสอบ (test) ใช้สำหรับรายงานผลสุดท้าย** และไม่ถูกใช้ในการฝึกฝนหรือการเลือกแบบจำลอง
- ทั้งสองรอบการทดลองประเมินบนชุดข้อมูลชุดเดียวกันทุกประการ เพื่อให้เปรียบเทียบกันได้
- ผลการประเมินทั้งหมดสร้างจากสคริปต์เดียวกันแบบอัตโนมัติ เพื่อให้ทำซ้ำแล้วได้ค่าเดิม
